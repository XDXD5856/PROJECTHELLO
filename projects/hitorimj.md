# HitoriMJ

> 类型：麻将 AI / 双人规则实验 / 训练与评测系统  
> 状态：Active  
> 正式代码：独立仓库

## 一句话

构建一个可以训练、评测并持续晋级的麻将 AI 系统，而不是只做一个会出牌的 demo。

## 当前核心

项目已经不只是模型训练，还包括：

- 自定义双人规则与模拟器；
- 数据收集和监督学习；
- bot 联赛与版本晋级；
- Web / Streamlit 等训练与观察 UI；
- standard 训练与正式验证；
- 对 ΔEV、配对区间、冠军切换、报告可信度的判断。

## 项目真正要证明的东西

不是“训练跑完了”，而是：

> 新版本在足够可信的对局设计下，是否真的比当前冠军更强。

因此 quick 流程只能验证工程链路，不能被当作实力提升证据。

## 重要想法

1. **版本化冠军体系**
   - 每个模型版本都有明确训练来源、配置、对局样本和晋级记录。
   - 当前 champion 不应因为偶然小样本波动而频繁切换。

2. **配对评测**
   - 尽量让候选模型与基线处在可比较的 seed / 局面条件下。
   - 报告同时给均值和区间，不只给单一胜率。

3. **AI 可解释接班**
   - 每一轮训练都自动留下：
     - config
     - progress
     - metrics
     - opponent
     - promotion decision
     - human-readable report

4. **UI 不是主角**
   - UI 应尽量紧凑、稳定、不闪烁，不让手牌因为无关区域更新而移动。
   - 实验可信度高于视觉复杂度。

## 下一阶段值得做

- 用 standard 而非 quick 流程证明模型强度变化；
- 建立稳定的 ΔEV 与置信区间判读规则；
- 检查 champion switching 是否对噪声过敏；
- 让报告能追溯到原始对局与配置；
- 再考虑更复杂策略、更多番种和更大模型。

## 不要做

- 不要把 quick 结果写成“模型变强”；
- 不要为了 UI 重构破坏训练链；
- 不要在缺少对局证据时手工宣布新冠军。
