# WorldFork 游戏概念草案

> 状态：Idea / 可继续推翻  
> 存放位置：PROJECTHELLO 仅保存想法；正式开发应迁移到独立 Private repo  
> 暂定标语：**Fork reality. Learn the cause. Carry knowledge across worlds.**

## 一句话

一款持续运行的因果策略游戏：一座由独立人物、关系、资源和消息驱动的城市会自行发展；玩家通过调查、预测、干预、回档和分叉时间线，学习世界真正的运行规律，并把知识从失败的世界带到下一个世界。

它不是“看 AI 小人聊天”，也不是有限剧情的选择游戏。

## 玩家是谁

玩家是世界之外的“档案员（Archivist）”。

档案员不能像上帝一样随意改数字，但拥有四类明确能力：

1. **观察**：追踪人物、关系、物资、地点与消息传播，寻找事件背后的因果链。
2. **接触**：每天只能直接联系极少数人物，提问、说服、警告、交易或撒谎。
3. **干预**：投放一件物品、一条消息、一笔资金、一次延误，或改变某个小型规则。
4. **分叉**：从任意已记录时刻创建平行世界，在不同分支实施不同方案并比较结果。

所以玩家的参与不是“偶尔按一下按钮”，而是：

> 观察现象 → 提出假设 → 建立对照分支 → 实施干预 → 比较结果 → 获得规律 → 用规律解决更难的问题。

## 最核心的游戏循环

每局不会直接告诉玩家真正原因。

例如，城市将在七天后发生暴乱。表面原因是粮价上涨，但可能的真实链条是：

```text
公交延误
→ 夜班工人迟到
→ 工厂解雇领班
→ 领班泄露仓库消息
→ 市民误以为粮食短缺
→ 抢购与暴乱
```

玩家可以在第四天建立两个分支：

- A：给市场投放更多粮食；
- B：让公交准时到站；
- C：公开仓库的真实库存。

三个世界会继续运行。玩家通过差异发现，解决危机的关键可能根本不是粮食，而是信息与信任。

最终乐趣来自“我真的找到了那根因果线”，而不是猜编剧准备的正确选项。

## 回档、重来与分叉

这些不是普通设置，而是游戏内能力。

| 操作 | 作用 | 代价 |
|---|---|---|
| 快照 Snapshot | 保存一个时间节点 | 占用有限档案槽 |
| 回溯 Rewind | 返回本分支的旧节点 | 当前节点之后的状态被标记为废弃历史 |
| 分叉 Fork | 从节点复制新世界 | 消耗稀缺的“稳定度” |
| 对比 Diff | 比较两个世界的人物、关系、资源和事件 | 需要玩家先选定观察范围 |
| 重启 Cycle | 用新 seed 生成新世界 | 世界清空，档案知识与已解锁工具保留 |
| 彻底清除 New Archive | 从零开始 | 删除全部元进度，作为明确的危险操作 |

失败的时间线不会毫无意义。玩家已经确认的因果规律、人物原型、事件图谱和工具，会保存在“档案馆”中。重开因此更像 roguelite 的下一轮，而不是重复劳动。

## 持续运行：一个不会等玩家的世界

世界没有传统的“通关后停止”。

- 游戏打开时，模拟按固定 tick 持续运行。
- 游戏关闭时，记录真实经过时间。
- 再次打开时，执行可复现的离线演算，并生成“你离开期间发生了什么”。
- 玩家可以设置离线速度上限，避免回来后整个世界已经不可辨认。
- 城市会出现新人物、新关系、新组织和新危机；旧人物会离开、衰老或死亡。
- 每个阶段会生成短期“档案任务”，但沙盒本身可以一直继续。

第一版完全本地运行，不要求常驻服务器。未来可以增加一个真正 24/7 的托管世界，但不是 MVP 的前提。

## 玩家为什么会持续回来

### 1. 动态档案任务

系统根据当前世界状态生成具有约束的目标，例如：

- 让两名敌对人物在不见面的情况下合作；
- 阻止银行挤兑，但不能注入资金；
- 让某人当选，同时不能让他知道玩家存在；
- 找出导致连续三次火灾的共同上游原因；
- 在两个分支中分别救下不同的人，再寻找第三种两人都能活下来的方案。

### 2. 因果图鉴

玩家发现的不是普通成就，而是可以复用的世界知识：

- 某类性格在什么条件下容易传播谣言；
- 价格、信任和恐慌如何相互强化；
- 哪些关系是表面相关，哪些是真正原因；
- 什么干预会产生延迟副作用。

图鉴中的规律可以有“已观察”“高度可信”“已通过对照实验确认”三个等级。

### 3. 时间线渗漏

当两个分支长期并行，人物可能收到另一个世界的梦、记忆碎片或物品。

这让分支之间不再完全隔离：

- 一个角色可能梦到自己在另一个世界的死亡；
- 玩家可以把一条信息跨世界发送，但内容会失真；
- 某些人物会逐渐意识到时间线存在；
- 过度渗漏可能产生新的危机。

它既是中后期机制，也是这个游戏最有辨识度的叙事来源。

## 扩展与更新方式

核心引擎和内容必须分离。扩展包使用版本化数据定义，而不是把所有内容写死在代码里。

一个扩展可以增加：

- 新地图与地点；
- 新职业、性格和需求；
- 新制度与经济规则；
- 新事件链和档案任务；
- 新的干预工具；
- 新视觉主题；
- 新世界 seed 规则。

建议结构：

```text
engine/          确定性模拟、时间线、存档、diff
client/          地图、人物面板、时间树、档案馆
content/core/    第一座城与基础事件
content/packs/   可插拔扩展
saves/           本地世界、快照与分支
schemas/         内容包和存档的版本规范
```

存档需要带 schema version 和迁移器，确保以后更新内容时旧世界尽可能可以继续运行。

## 失败方式与长期张力

玩家不是无限强。主要资源可以只有三种：

- **注意力**：同时能深入追踪的人和事件有限；
- **影响力**：直接干预世界的次数有限；
- **稳定度**：维持平行时间线需要成本。

如果玩家无止境分叉，世界之间会出现渗漏；如果完全不干预，世界仍会前进并形成玩家难以理解的复杂历史。

这使“观察多久、何时下注、保留哪个分支”成为真实决策。

## 第一版应该做什么

MVP 的目标不是假装拥有无限 AI，而是证明“分叉—对照—发现因果”真的好玩。

### MVP 内容

- 12 名有记忆、需求、关系和简单计划的角色；
- 3 个地点；
- 1 个会在七天后发生的城市危机；
- 20 个可观察事件；
- 8 种玩家干预；
- 最多 3 条并行时间线；
- 快照、回溯、分叉和结构化 diff；
- 一个能显示事件因果链的调查板；
- 关闭后可进行有限离线演算；
- 同 seed + 同操作得到相同结果。

### 暂时不做

- 不让大语言模型决定核心模拟；
- 不做大型开放地图；
- 不做多人在线；
- 不做无限自然语言对话；
- 不做真实 24/7 云服务器；
- 不先堆几十个角色。

LLM 以后可以负责角色语言表达、新闻和档案摘要，但世界状态与因果必须由确定性引擎决定，否则玩家无法通过实验真正学习规律。

## 技术方向（仅为未来独立项目的候选方案）

- TypeScript monorepo；
- React + Canvas/PixiJS 作为地图与 UI；
- 独立 simulation package，不能依赖界面；
- IndexedDB 保存本地世界；
- Web Worker 运行模拟，避免卡住 UI；
- 基于事件日志重放与重建世界；
- seedable PRNG 保证可复现；
- JSON Schema 定义内容包与存档；
- GitHub Pages 可直接试玩。

以上不会直接在 PROJECTHELLO 内实现。概念通过验证后，再选择或创建独立 Private repo。

## 当前最需要验证的问题

在搭完整框架前，先做一个极小的垂直原型回答三件事：

1. 只看两条时间线的差异，是否已经产生“侦破因果”的爽感？
2. 玩家每天有限的接触和干预，是否足以让参与感成立？
3. 离线后世界继续演化，会让人期待回来，还是只会制造错过焦虑？

如果这三点成立，WorldFork 才值得进入正式开发。

## 当前结论

WorldFork 的核心不应是“AI 社会会自己发生什么”，而应该是：

> **你用版本控制一样的方式研究现实，并把失败世界的知识带往下一轮。**

下一步应先在独立 Private repo 制作一个 10–15 分钟可玩的垂直原型，再决定最终美术、世界观和长期内容。
